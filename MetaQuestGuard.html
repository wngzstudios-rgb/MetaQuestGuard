Attestation-driven anti-cheat for Meta Quest VR.

Built after analyzing real world cheats. Detects Unity-specific tools like MelonLoader, BepInEx, and other common threats — read-only, user-mode, on a worker thread, with zero performance hit for honest players. Design principles

Standalone, attestation-native.

MetaQuestGuard is built directly on Meta's platform primitives. No third-party anti-cheat cloud. No invasive client inspection.

Highly effective

Built after analyzing real world cheats. Detects Unity-specific tools like MelonLoader, BepInEx, and other common threats — not a generic signature list.

Zero risk

Read-only, user-mode, and runs in a worker thread — no performance hit, no impact on honest players. Never blocks, patches, or touches another process.

Unity tailored

Runs Unity-specific checks and bakes directly into your IL2CPP assembly — no obvious AntiCheat.dll file, fully embedded.

Netcode agnostic

Works with any multiplayer Unity game. A Mirror Networking integration ships today, with more transports on the roadmap.

Privacy focused

No cloud, no tracking. Only scans the game process & folder. Sends signed reports to your own game server — never a third party.

Silent reporting

Guard never blocks — only sends reports quietly to the server. Cheaters stay unaware and assume they were caught by other players.

Cross-platform C#

100% C# IL code. Compiles on all Unity platforms. Detects cheats on Windows and Meta Quest, with zero Quest-incompatible PC-only checks in the Quest build.

Easy to use

A single component. Every cheat is reported through one event: OnDetected(confidence, type, evidence).

Attestation-native trust

Meta Attestation tokens are cached for their full validity window — never a heartbeat. Advanced device integrity passes; Basic is gated unless you opt in.

Security patch gating

Sessions report the device's OS security patch date. Anything older than 30 days is treated as needing an update, the same way a failed attestation is.

GorillaLocomotion-aware (v2)

Dedicated validator for hand-over-hand momentum climbing. Now includes surface-contact checks, post-release velocity continuity, height-gain limits, rubber-band detection, statistical baselines, history buffer, and physics prediction.

Obfuscated release build

Ship the obfuscated DLL (ConfuserEx / Obfuscar / commercial IL obfuscator + string encryption). Source stays internal. Guard self-integrity hashes critical method bodies against a baseline signed into the play token.

Guard anti-tamper

Integrity self-check of Guard assemblies, signed worker-thread alive pings the server can expect, and protection against suspension of the background scanner.

Stronger injection detection

Beyond name lists: HarmonyMethod / PatchProcessor type graphs, /proc/self/maps path checks for libunity/libil2cpp, and System.Reflection.Emit dynamic codegen signals.

Anti-false-positive toolkit

Per-detection confidence thresholds, temporary suppression windows after legitimate high-intensity actions, kinematic history for server re-validation, and coalesced detection-storm reports.

Photon opt-in helpers

AntiRPCSpam (rate-limits event 200/202) and AntiMasterClientSwitch ship as optional components. Guard core stays silent; these scripts are the explicit enforcement surface.

Integration guide

Three-step bootstrap.

Add the component, run attestation, subscribe to detections. Your server gates the response.

1
Attach the component
Drop MetaQuestGuard.cs into your project. Add the MetaQuestGuard component to a persistent root GameObject. Set your backend report endpoint, security-patch threshold, and device-integrity policy in the Inspector.
2
Bootstrap after Meta SDK init
Call MetaQuestGuardBootstrap.Run() once with the user proof, attestation token, and backend URL. Guard caches the returned session — no heartbeat is ever generated, and the worker thread starts automatically once bootstrap succeeds.
3
Server-side validation loop
On your authoritative game server, use MetaQuestGuard.ValidateInputCommand() for generic VR input, or GorillaLocomotionGuard.ValidateFrame() if your movement is hand-over-hand climbing. Gate ranked play behind IsAllowedHighValueAction(). Runtime detections forward automatically via OnDetected.
4
Optional: wire your netcode
Add MetaQuestGuardMirrorIntegration.cs (guarded by the MIRROR define) if you're on Mirror Networking. Other transports follow the same one-file bridge pattern.
GameManager.cs
// Subscribe to detections (silently, server-side only) _guard.OnDetected += (confidence, type, evidence) => {   ModerationPipeline.Log(confidence, type, evidence); };

// After Meta SDK initializes — runs once, no heartbeat yield return StartCoroutine(MetaQuestGuardBootstrap.Run(   _guard,   backendUrl: "https://your-server.example.com/bootstrap",   metaUserId: user.Id,   userProofNonce: userProofNonce,   attestationToken: attestationToken,   onComplete: (ok, sessionId) => { if (!ok) ShowUpdateOrErrorPrompt(); } ));

// Gate ranked play — Advanced integrity + current security patch required if (_guard.IsAllowedHighValueAction(out var denyReason))   JoinRankedQueue();
